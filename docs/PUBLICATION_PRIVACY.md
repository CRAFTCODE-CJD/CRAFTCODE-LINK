# Проверка исходников перед публикацией

В корне своей копии выполните `python scripts/git-privacy.py install`. Нужны Python 3.9+ и Git 2.55+ для установки. Команда добавляет две именованные проверки в локальную конфигурацию этого репозитория. Значение `core.hooksPath`, другие проверки и обработчик Git LFS сохраняются. На более старом Git доступны ручные команды ниже.

Перед коммитом проверяется полный индекс Git, включая файлы, добавленные принудительно. Перед отправкой проверяются все новые коммиты передаваемых веток и тегов, их сообщения, имена файлов и точные байты объектов Git. При создании нового тега проверяется доступная из него история. Поэтому удаление файла в следующем коммите не скроет его из проверки. Если образовался локальный коммит с личными данными, сначала пересоберите ещё не опубликованную историю. Удаление секрета с уже опубликованной ветки требует также отзыва секрета.

Проверка распознаёт профили LINK, диагностические дампы, базы, временные каталоги, архивы, ключи, распространённые токены, абсолютные пути профиля и данные LINK. Единственный разрешённый архив исходников FFmpeg сверяется по пути и закреплённому SHA-256. Указатели LFS требуют отдельной проверки содержимого и блокируются в этой политике публикации. На этом ПК дополнительно проверяются имя учётной записи и имя устройства. Если в текстах встречаются ваши личные имена, адреса или другие логины, внесите их в файл `.link-private-terms` в корне рабочей копии, по одному значению на строку. Он исключён из Git, а в сообщении об ошибке совпавшее значение скрыто. В CI работает публичный набор признаков. Локальный словарь в CI не передаётся. Техническая проверка не распознает лица, речь и переписку на скриншотах и в видеороликах. Перед выпуском просмотр этих материалов остаётся частью проверки.

Локальные команды

| Действие | Команда |
| --- | --- |
| Проверить точное содержимое индекса | `python scripts/git-privacy.py index` |
| Проверить всю историю текущей ветки | `python scripts/git-privacy.py history HEAD` |
| Проверить коммиты после базового тега | `python scripts/git-privacy.py history HEAD v0.7.18` |
| Проверить релиз с публичной подписью автора и коммиттера | `python scripts/git-privacy.py history v0.7.18 --release` |
| Посмотреть установленные обработчики | `git hook list pre-commit` и `git hook list pre-push` |

В официальной рабочей копии издателя выполните `python scripts/git-privacy.py install --publisher`. При отправке `main` и тегов этот режим дополнительно проверяет публичные поля Git у новых коммитов, а у аннотированных тегов также автора тега. Для этой копии настройте `git config --local user.name CRAFTCODE-CJD` и присвоенный аккаунту адрес `users.noreply.github.com` из настроек GitHub. Проверка поддерживает адреса с числовым префиксом GitHub и старую форму без префикса. Новые выпуски публикуйте из проверенного коммита. Обычные контрибьюторы устанавливают проверку без флага издателя и сохраняют своё авторство.

Для удаления только установленных здесь настроек используйте `git config --local --remove-section hook.link-index-privacy`, `git config --local --remove-section hook.link-push-privacy`, а после установки режима издателя также `git config --local --unset craftlink.privacyPublisher`.

The contributor install checks staged Git objects and outgoing history, including files deleted again before the push. Add private terms only to your ignored local dictionary. Official release clones also opt into the project noreply identity using `install --publisher`. Direct GitHub uploads and clients that skip local hooks still require review. CI checks source after the server has received it.
