# Android и RuStore — подготовка выпуска CRAFTCODE LINK

Проверено 11 ноября 2026 года. Это план выпуска Android, а не сообщение о готовом мобильном приложении. В проверенной сборке проекта есть Windows-клиент 0.7.14. Android-проект, подписанный APK, карточка RuStore и проверка на телефоне пока отсутствуют. Инструкции Windows находятся в [GITHUB_RELEASE_RU.md](GITHUB_RELEASE_RU.md).

## Формат и постоянная идентичность приложения

Для первого мобильного выпуска предлагается самостоятельно подписанный APK, одинаковый в GitHub Releases и RuStore. Это позволит сохранить данные при обновлении из другого канала при совместимой сборке, прежней подписи и увеличенном `versionCode`. До первого выпуска нужно окончательно выбрать `applicationId`. Предложение — `io.github.craftcodecjd.link`, отдельное `.debug` для разработки. Идентификатор пока не зарегистрирован и должен совпасть с мобильным проектом.

Каждый устанавливаемый APK требует подписи. Производственный ключ создаёт владелец выпуска, хранит вне репозитория и резервирует отдельно. В исходники и общедоступные задания сборки не попадают ключ, пароль или экспорт профиля. В журнал выпуска записываются отпечаток сертификата, `applicationId`, `versionName`, `versionCode` и SHA-256 артефакта. [Подпись приложений Android](https://developer.android.com/studio/publish/app-signing).

RuStore принимает APK и AAB до 5 ГБ. При обновлении APK нужны прежние package name и подпись, возрастающий `versionCode`. Для первого AAB магазин запрашивает ключ подписи приложения через свою процедуру и сертификат загрузки, затем подписывает сформированные APK. Поэтому переход к AAB — отдельное решение владельца о хранении ключа, а не автоматический шаг сборки. [Публикация APK](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication), [подготовка AAB](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication/new-version-app/upload-aab).

## Карточка приложения

Следующий текст — заготовка для первой Android-версии после проверки перечисленных функций. Если какая-либо функция не попадёт в APK, её нужно убрать из карточки до подачи.

**Название:** CRAFTCODE LINK

**Краткое описание:** Личные чаты, голосовые сообщения и звонки для друзей.

**Полное описание:**

CRAFTCODE LINK — приложение для общения со своими людьми. Создайте профиль, добавьте друзей и общайтесь в личных чатах. Отправляйте сообщения, фотографии, выбранные файлы и голосовые записи. Когда удобнее поговорить — переходите к звонку.

Ваша личная история хранится на ваших устройствах. Очистку истории и скачанных вложений можно выполнить в настройках чата. Доставка зависит от доступности устройств и выбранного способа соединения.

LINK развивается как проект с открытым исходным кодом. Актуальные возможности, ограничения совместимости и изменения каждой версии доступны в репозитории CRAFTCODE-CJD/CRAFTCODE-LINK.

Приложение бесплатно. Поддержка разработки добровольная и не открывает платные возможности.

**Категория:** выбрать подходящую категорию общения в актуальной консоли. **Возрастной рейтинг:** заполнить анкету по фактическим возможностям APK, не назначать возраст по предположению. **Поддержка:** сайт репозитория `https://github.com/CRAFTCODE-CJD/CRAFTCODE-LINK`, после его публичного открытия. Личный email автора не подставлять без его указания.

RuStore ограничивает название 30 символами, краткий текст 80, полный 4000. Нужен хотя бы один контакт разработчика. Иконка — 512 × 512, PNG/JPG, непрозрачный фон, до 3 МБ. Для телефона подготовить минимум три настоящих скриншота, каждый PNG/JPG до 3 МБ, разрешение не выше 2160 × 3840. Снимки Windows не заменяют снимки Android. [Поля и материалы карточки](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication).

Предлагаемые три сцены — личный чат с изображением и голосовым сообщением, звонок с участниками, профиль и оформление. На снимках использовать тестовых пользователей. Не включать реальные сообщения, контакты, QR-карточки дружбы или ключи. Планшеты и другие виды устройств отмечать поддерживаемыми только после отдельной проверки.

## Обновления

Windows-модуль `src/github-releases.cjs` принимает только проверенный установщик `Setup-x64.exe`. Он проверяет размер, SHA-256 и адрес скачивания, но не реализует Android-установку. Этот модуль не следует расширять разрешением на произвольный исполняемый файл.

Для варианта из RuStore нужен Android-адаптер официального In-app updates SDK. На дату проверки актуальна версия 10.5.2, BOM 2026.10.01. SDK проверяет доступность RuStore, авторизацию и отсутствие блокировки пользователя или приложения. Обновление проходит через состояния проверки, загрузки и установки. После ошибки или повторной попытки требуется новое состояние SDK. Рекомендуемый режим LINK — отложенная установка по действию пользователя, когда закончены звонки и передачи. [Актуальный SDK обновлений](https://www.rustore.ru/help/sdk/updates/kotlin-java/10-5-2).

Для APK с GitHub до реализации собственного безопасного Android-обновления показывать страницу официального релиза. Не запрашивать разрешение установки других приложений только ради версии из RuStore. Один ключ и номер пакета сами по себе не гарантируют переход между каналами — его нужно проверить установкой обеих последовательностей с сохранением профиля. Не обещать бесшумную установку, если её не разрешают Android и выбранный магазин.

В любом канале отмена обновления оставляет текущую версию работоспособной. Нет сети, нет RuStore, ошибка проверки и отказ пользователя — отдельные состояния с понятной повторной попыткой. Обновление не должно обрывать текущий разговор.

## Разрешения, данные и фоновая работа

Разрешения определяются реальным AndroidManifest после реализации. Предлагаемый минимальный набор включает интернет, микрофон для голосовой записи и звонка, камеру для видеозаписи и уведомления. Микрофон и камера запрашиваются при соответствующем действии. На Android 13+ обычные уведомления требуют отдельного согласия `POST_NOTIFICATIONS`. [Разрешение уведомлений Android](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

Файлы выбирать системным диалогом, не запрашивать доступ ко всему накопителю. Синхронизацию телефонной адресной книги, SMS, геолокацию, доступность системы и VPN не добавлять без отдельной реализованной функции. Windows LAN-адаптер Wintun на Android не переносится. Работа голосового вызова в фоне, экранная трансляция, Bluetooth-гарнитуры и ограничения батареи требуют отдельной реализации и проверки разрешений на поддерживаемых версиях Android.

Будущий push-сервис должен передавать уведомление о событии с минимумом данных. Не помещать текст переписки, имя собеседника или ключи в открытые поля уведомления провайдера. Сервисный токен RuStore Push хранится только на стороне доверенного отправляющего сервиса, никогда внутри APK. Наличие такого сервиса изменяет перечень получателей данных и должно попасть в политику. [Отправка RuStore Push](https://www.rustore.ru/help/sdk/push-notifications/send-push-notifications).

Черновик [PRIVACY_RU.md](PRIVACY_RU.md) описывает текущий Windows-клиент. До публикации Android нужно сверить его с фактическими SDK, push-сервисом, местом хранения ключей, переносом профиля и хранением сообщений. Анкету «Безопасность данных» RuStore заполнять по APK и его сетевым обращениям. Нельзя отмечать «никакие данные не передаются» для мессенджера, передающего сообщения, выбранные вложения и данные соединения другим участникам.
