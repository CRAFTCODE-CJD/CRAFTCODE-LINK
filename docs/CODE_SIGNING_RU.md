# Подпись выпусков CRAFTCODE LINK для Windows

## Текущее состояние

Проверено 11 ноября 2026 года. Сборка 0.7.14 распространяется без авторской подписи Authenticode. В хранилищах Windows CurrentUser\My и LocalMachine\My найдено 0 сертификатов Code Signing. Следующий этап — выбор поставщика, проверка владельца и получение доступа к подписи.

В BUILD-INFO.json записано signedByCRAFTCODE=false. Контрольные суммы релиза позволяют проверить содержимое загруженных файлов. Authenticode дополнительно связывает файл с проверенным издателем. Репутация новых подписанных приложений формируется со временем. [Microsoft о SmartScreen](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

## Варианты

### SignPath Foundation

Для принятого Open Source проекта фонд бесплатно предоставляет подпись и защищённое хранение ключа. В подписи указывается SignPath Foundation. Фонд проверяет открытые исходники, лицензию, поддержку проекта, репутацию, происхождение сборки и процесс одобрения подписей. Приём нового репозитория зависит от решения фонда. [Программа](https://signpath.org/), [условия](https://signpath.org/terms).

Для LINK нужно согласовать состав поставки, включая брендированный Electron. Текущий GitHub workflow выполняет проверки. Для SignPath предстоит подключить сборку распространяемых файлов через согласованную CI-интеграцию.

### Microsoft Artifact Signing

Basic стоит $9.99 в месяц за 5 000 подписей. Дополнительная подпись стоит $0.005. Налоги и итоговая стоимость зависят от аккаунта. [Тарифы Microsoft](https://azure.microsoft.com/en-us/products/artifact-signing).

Для физических лиц Public Trust доступен в США и Канаде. Для организаций поддерживается более широкий перечень стран. Россия отсутствует в опубликованном перечне. Доступность для автора LINK предстоит установить по данным владельца. Требуются проверка личности и подходящая платная подписка Azure. [Доступность и проверка владельца](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart), [FAQ](https://learn.microsoft.com/en-us/azure/artifact-signing/faq).

### Сертификат удостоверяющего центра

SSL.com предлагает Individual Validated Code Signing за $129 на один год. Хранение ключа оплачивается дополнительно, например аппаратный токен за $379 или облачная услуга. Доступность для страны автора и окончательная стоимость требуют проверки перед заказом. [SSL.com IV Code Signing](https://www.ssl.com/products/software-integrity/code-signing/iv/).

## Порядок интеграции в сборку LINK

1. Зафиксировать проверенный исходный коммит и версии инструментов.
2. Завершить изменение имени и ресурсов Electron в package-win.cjs, собрать собственные Go-помощники. Затем подписать главный EXE и согласованные собственные бинарники.
3. Сохранить подписи и исходные байты сторонних компонентов, включая Wintun. Состав файлов для авторской подписи согласовать с поставщиком.
4. Подписать care.exe после go build в package-setup.py и перед включением помощника в NSIS.
5. Подписать сформированный Uninstall.exe через механизм NSIS !uninstfinalize, затем включить его в установщик. [Документация NSIS](https://nsis.sourceforge.io/Docs/Chapter5.html).
6. Собрать Setup, подписать окончательный EXE и проверить доверие Windows, ожидаемого издателя и RFC 3161-метку времени.
7. Проверить запуск, обновление и удаление во временном каталоге. Проверить подписи установленных EXE, помощников и деинсталлятора.
8. Создать Portable ZIP из подписанного содержимого. Отразить реального издателя и покрытие подписью в BUILD-INFO. Затем сформировать Source.zip, FILES.sha256, SHA256SUMS.txt и Update-Code через handoff.cjs.

Ошибка подписи или её проверки останавливает подготовку подписанного выпуска. Подписанные файлы поступают в упаковку в окончательном виде. Пересборка уже опубликованной версии с новой подписью получает новый номер версии и новые контрольные суммы.

JavaScript в resources/app защищён подписью установщика при распространении. Контроль целостности этих файлов после установки требует отдельного механизма.

Для SignTool выбираются конкретный отпечаток сертификата, SHA-256 для файла и RFC 3161-сервер его поставщика. Проверка через verify /pa /all /tw /v должна завершиться кодом 0. Дополнительно проверяются Status=Valid, ожидаемый издатель и TimeStamperCertificate. Для облачной подписи проверка учитывает ожидаемую личность и профиль при штатной смене краткоживущих сертификатов. [SignTool](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool), [интеграции Artifact Signing](https://learn.microsoft.com/en-us/azure/artifact-signing/how-to-signing-integrations).

## Kaspersky и запрос микрофона после обновления

Статус проверки двух официально подписанных версий — **NOT TESTED**. Изменение EXE и отсутствие авторской подписи рассматриваются как возможная причина повторных запросов. Для установления причины на компьютере пользователя нужны сведения из запроса и журнала Kaspersky.

Kaspersky учитывает поведение, репутацию, электронную подпись и целостность приложения. Доступ к камере и микрофону контролируется дополнительно. Поведение после подписанного обновления зависит от правил конкретного продукта. [Контроль приложений](https://www.kaspersky.com/enterprise-security/wiki-section/products/application-control-and-hips), [доступ к микрофону](https://support.kaspersky.com/help/kaspersky/win21.20/ru-RU/94351.htm).

Проверка проводится со штатной защитой и разрешениями владельца.

1. Зафиксировать версии Windows и Kaspersky, путь, SHA-256 и подпись версии A.
2. Установить A в штатный %LOCALAPPDATA%\Programs\CRAFTCODE LINK. Получить разрешение владельца через обычный запрос и проверить звонок и голосовое сообщение.
3. Обновить до B с тем же проверенным издателем, путём и AppUserModelID CRAFTCODE.Link.Desktop.
4. Повторить звонок, запись и перезапуск. Записать текст повторного запроса, имя процесса, путь и группу доверия.
5. Отдельно отметить запрос разрешения и уведомление об использовании микрофона. При неоднозначном результате повторить ещё одно обновление.

Постоянные путь и AppUserModelID уже заданы в LINK. Результат проверки антивируса фиксируется по фактическому поведению.
